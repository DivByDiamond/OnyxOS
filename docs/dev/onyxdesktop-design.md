# OnyxDesktop — дизайн (draft, 2026-11-21)

Статус: на утверждении. Решение владельца: отдельный репозиторий
`OnyxDesktop`, «смешанный» WM+DE, старт на QEMU-пути.

## Зачем

Дать Onyx полноценный десктоп, который можно запускать на одноплатнике
с экраном: панель, лаунчер, переключение приложений, затем — окна.
Сейчас GUI-приложения рисуют в `/dev/fb0` напрямую, общего экранного
пространства, фокуса и переключения нет.

## Что уже есть (проверено в коде)

- `FB_IOCTL_CLAIM_GRAPHICS` / `FB_IOCTL_RELEASE_GRAPHICS` — эксклюзивный
  захват `/dev/fb0` (os: `fs/devfs/vnode.rs`).
- `SYS_mouse_read` — состояние курсора и кнопок.
- `SYS_kill` с job-control: `SIGSTOP`/`SIGCONT` реально паркуют и будят
  процесс (`proc/signals/handler.rs`, `proc/process/types.rs`).
- `spawn`/`exec`/`wait`, `/ipc`-каналы, `mmap` fb.
- C99-компилятор, собирающий GUI-приложения (`ochat-gui`, `otablet`).

## Что НЕ нужно от ядра для v1 (и почему не делаем это первым)

MVP не блокируется ядром или компилятором. Всё необходимое — claim fb +
mouse + kill + spawn — уже есть. Работа «сначала ядро/компилятор» не
разблокирует десктоп, поэтому она переносится в prerequisites будущих
вех (ниже), а не в блокеры.

## Prerequisites, записанные в план (не блокируют v1)

- **Ядро P2-A: доставка ввода выбранному процессу.** Сейчас клавиши идут
  в TTY; WM-хоткеи (Alt+Tab и т.п.) потребуют канала «ввод → desk» без
  перехвата TTY. Нужно к M3 (окна/фокус), не к v1.
- **Ядро P2-B: общие поверхности.** Перекрывающиеся окна требуют
  клиентских буферов (memfd-подобный объект + mmap + композиция).
  Нужно к v2 (M4), не к v1.
- **Компилятор: блокеров нет.** C99 достаточно; при желании C++-subset
  (классы/RAII/virtual) уже есть.
- **Железо: отдельный трек.** SDHCI/USB(OC2R-путь GHCI)/DSI/GMAC под
  SG2000 собраны, но live-проверки требуют платы. Чек-лист bring-up —
  в `OnyxKernel/todo.md` (Duo S), не блокирует QEMU-разработку.

## Цели v1 (M0–M2)

1. `onyxdesk` — C99-демон, захватывает fb, рисует панель (часы, имя
   активного приложения) и лаунчер (список GUI-приложений из
   `/etc/desk.conf`).
2. Запуск приложения на весь экран; возврат в лаунчер — **по выходу
   приложения** (клавиша выхода самого приложения / его штатное
   завершение). Пауза/переключение живых приложений (`SIGSTOP`/
   `SIGCONT`) — **M3**, вместе с ядерной доставкой ввода (P2-A):
   маршрутизации ввода нет, а `mouse_read` раздаёт общие клики из
   одной очереди, поэтому v1 не притворяется, что умеет переключение.
3. Конфиг `/etc/desk.conf` (`key=value` + список приложений).
4. Дисциплина экрана: desk держит `CLAIM_GRAPHICS` **весь сеанс**;
   приложения запускаются в «managed» режиме и сами claim не делают;
   консольная печать ядра подавлена на время сеанса (логи — в UART);
   при выходе desk — release.
5. Host-тесты чистой логики (парсер конфига, layout панели, state-машина
   `Launcher ⇄ Active`) + QEMU headless smoke по serial-логам
   (`DESK_READY`/`APP_STARTED`/`APP_RETURN`); pointer/pixel-харнесс на
   QEMU monitor — следующим шагом.

## Про `otablet` (решение владельца)

`OnyxApps/apps/otablet` остаётся **отдельным** лёгким планшетным UI
(малое потребление, свой desktop-режим). Ничего не поглощаем и не
удаляем. OnyxDesktop — самостоятельный десктоп-сеанс; при реализации
v2 (окна) допускается переиспользовать идеи/фрагменты алгоритмов, но
общий код не навязывается.

## Non-goals v1

- Перекрывающиеся окна, декор, z-order (v2).
- Темы, drag&drop, тач, мультимонитор, DPI.
- Композитор/фокус в ядре — только userspace.
- GUI-тулкит: приложения остаются «рисуют в fb сами» до v2.

## Рассмотренные подходы

- **A (выбран): userspace-демон владеет fb, v1 — полноэкранное
  переключение с pause/resume.** Использует существующие примитивы,
  растёт к v2 без переделки.
- B: композитор в ядре — отвергнут (политика в ядре, нарушает слои).
- C: только полноэкранные приложения без переключения — отвергнут
  (не тянет к DE).

## Архитектура

Репозиторий `OnyxDesktop`:
- `onyxdesk/` — демон: main + state-машина (`launcher → active →
  suspended`), fb-обвязка (claim/release, blit панели), spawn/kill.
- `config/` — парсер `/etc/desk.conf`.
- `ui/` — панель/лаунчер, чистая отрисовка в буфер.
- `tests/native/` — host-тесты (state-машина, парсер, layout).
- CI: native-тесты + сборка `onyxdesk.onx` (ONX1) как в OnyxApps.

Поток (v1): desk стартует → claim fb (на весь сеанс) → рисует
панель+лаунчер → по выбору `spawn(app)` в «managed» режиме (приложение
рисует в fb напрямую и само claim не делает) → desk `wait()` ждёт →
при выходе приложения перерисовывает лаунчер (claim не отпускал) →
выход desk → release. Claim — advisory-флаг: он подавляет консольную
печать ядра и помечает владельца, но запись в fb другим процессам не
блокирует — поэтому managed-приложения рисуют легально.

Состояния v1: `Launcher` ⇄ `Active(pid)` (без Suspended). M3 добавляет
`Suspended(pid)` (`SIGSTOP`/`SIGCONT`) вместе с ядерной доставкой ввода.

## Вехи

- **M0:** репо + скелет демона: claim/release, панель, чистая логика +
  host-тесты.
- **M1:** лаунчер, managed-запуск, `wait`, возврат и перерисовка,
  QEMU headless smoke по serial-логам.
- **M2:** интеграция GUI-приложений (managed-режим `otablet`/`ochat-gui`),
  устойчивость к падениям, `/etc/desk.conf` в образе.
- **M3 (после P2-A ядра):** хоткеи, доставка ввода активному окну,
  `SIGSTOP`/`SIGCONT`-переключение, перерисовка после resume.
- **M4 (после P2-B ядра):** перекрывающиеся окна/композиция.
- **SBC-трек:** чек-лист bring-up на плате; проверка DSI-экрана и USB-HID
  вживую; `onyxdesk` — первый UI-сценарий.

## Риски

- Полноэкранный v1 упирается в «приложение должно уметь жить в
  полноэкранном fb» — существующие GUI-приложения умеют.
- Между кадрами fb переходит между desk и приложением — нужна чёткая
  дисциплина claim/release и обработка «приложение упало, держа claim».
- На SBC перерисовка может быть медленной (пиксельный blit) — v1
  рисует минимум (панель), приложения — сами.

## Решённое (builder-check, решения контроллера)

- **Ввод в v1** не маршрутизируется: v1 не делает SIGSTOP-переключение;
  выход из приложения — его собственный механизм; M3 закрывает P2-A.
- **Claim** — advisory: desk держит его весь сеанс; managed-приложения
  не claim-ят; консольная печать подавлена, логи в UART.
- **Старт:** вручную из `osh`; desk — ring 1 (гейт `SYS_spawn`/
  `SYS_kill`); автозапуск `/service` не в v1 (конфликт респавна login).
- **Упаковка:** OnyxDesktop — 7-я `.vent`-зависимость; шаг образа в
  `build-apps.py`/`mk-onyxfs-disk.sh`; `/etc/desk.conf` кладётся образом.
- **Лаунчер** — только GUI-приложения из конфига; терминальные остаются
  в шелле.
- **Гейт M1** — headless serial-логи; pointer/pixel-харнесс на QEMU
  monitor (`sendkey`/`mouse_*`/`screendump`) — следующий шаг. Sedna
  smoke — опционально.
- **otablet** остаётся отдельным планшетным UI (см. выше), без
  поглощения.
